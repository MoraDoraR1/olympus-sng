## 0. v1 대비 주요 변경점 (요약)

- 야생 지역(몬스터)이 **성벽 위에 절대좌표로 흩뿌려지던 방식 → 성벽 위쪽에 가로로 흐르는 한 줄 배너**로 변경(겹침 걱정 없이 문서 흐름을 따름).
- 건물 타일이 **패널(카드) 배경을 벗고 아이콘만 둥둥 뜨는 스타일**로 변경 → 이제 배경/바닥 텍스처가 없으면 화면이 휑하다. 배경 아트가 사실상 필수가 됨.
- **성벽(wall)은 그리드 타일이 아니라 성벽 프레임(테두리) 자체를 클릭**해서 짓는 "메타 건물"이 됨.
- **월드맵**이 모달이 아니라 완전한 화면 전환(레벨 1~20 성 침공, 지그재그 배치)으로 추가됨.
- **타이틀/종료 화면**이 전체화면 오버레이로 추가됨(z-index 500, 모달보다도 위).
- **설명서, 보유 영웅** 모달 2개 신설. 건물 모달은 `modal-xwide`(1140px) + 정보/비교/영웅배치(+병영이면 훈련) 다열 구성으로 확장.
- 자원바에 **초당 생산량(rate)** 표시 추가, 방어탑 의미가 "수비 수치"에서 "원정 부대 강화%"로 변경, 등급이 ★7 → **★8**까지 확장(까미는 별도).
- 아이콘 전반에 **idle-float(둥실둥실 부유)** 애니메이션이 공통 모션 문법으로 적용됨(건물/몬스터/월드맵 성 전부 동일 리듬).
- **도시 평면(성벽+보드)에 가벼운 2.5D 틸트**가 추가됨. `.kingdom-stage`에 `perspective: 900px`, `.wall-frame`에 `transform: rotateX(30deg); transform-origin: top center;`를 적용해 "위에서 비스듬히 내려다보는" 느낌을 줌. 몬스터 배너(`.monster-grid`)는 이 틸트 밖에 있어 평평하게 유지됨.

## 1. 화면 전체 구조 (v2 시점 5개 상태 + 이후 추가된 로그인 화면)

이 게임은 SPA처럼 화면 전체가 전환되는 최상위 화면 상태를 가진다. 동시에 두 개 이상 보이면 안 된다.

| 상태 | 요소 id | 트리거 |
|---|---|---|
| **로그인**(v2 이후 신설) | `#screen-login` | 최초 로드 시 토큰 없음/만료 — 닉네임+비밀번호 |
| 타이틀 | `#screen-title` | 로그인 성공 직후 |
| 도시(기본) | `#kingdom-stage` + `#kingdom-label` | "게임 시작" / "도시로 돌아가기" |
| **정복(PvP) 맵**(v2 이후 성격이 바뀜) | `#screen-worldmap` | "⚔️ 정복" 버튼(`#btn-worldmap`) — **더 이상 NPC 성 화면이 아니다.** 실제 플레이어끼리 겨루는 200×200 드래그형 맵(10절 참고). 이 화면/DOM이 원래 있던 "월드맵"(NPC 성) 화면 이름·버튼을 그대로 물려받았다 |
| 종료 | `#screen-outro` | "🚪 종료" 버튼 |
| (공통) 모달 | `.modal-overlay` 다수 (건물/교전/레이드/**침략**/인벤토리/영웅/설명서/튜토리얼 등, v2 이후 계속 늘어남) | 각 액션 버튼 — 위 화면들 위에 겹쳐 뜸 |

**NPC 성 20개(원래 "월드맵"이었던 콘텐츠)는 화면이 아니라 모달이다** — topbar의 "🏯 침략"
버튼(`#btn-worldcastles`) → `#modal-worldcastles`. 5절 참고.

z-index 순서: `#topbar`(20) < `.wall-frame`/`.board-wrap`(2) < `.modal-overlay`(100) < `#toast-layer`(300) < `.screen-title`(500, 타이틀/종료/로그인 전용).

**규칙**: 타이틀·종료·로그인 화면은 topbar까지 완전히 덮어야 하므로 z-index 500 + `position: fixed; inset:0`을 유지한다. 새 풀스크린 화면을 추가할 때도 이 값 이상을 쓸 것.

## 2. 도시 화면(`.kingdom-stage`) — 세로 스택 구조

이제 `.kingdom-stage`는 `display:flex; flex-direction:column; align-items:center; gap:10px`로, **위에서부터 문서 흐름 순서대로** 쌓인다(더 이상 절대좌표 오버레이 아님).

1. `.monster-grid` — 야생 지역, 가로로 흐르는 flex-wrap 배너(성벽 위쪽)
2. `.wall-frame` → 그 안에 `.board-wrap` → `#board`(성벽 안 도시 그리드)

**배치 규칙**: 새 구역(예: 항구, 외곽 마을)을 추가한다면 이 세로 스택 순서에 새 `<div>`를 끼워 넣는 방식으로 확장한다. 절대좌표 오버레이로 되돌리지 말 것 — 반응형에서 깨지기 쉽다.

### 2-1. 몬스터 배너(`.monster-grid`)

- `position: static; display:flex; flex-wrap:wrap; justify-content:center; gap:8px`
- 카드 폭 106px(900px 이하에서 84px), 카드 자체엔 배경/그림자 없음(`background:transparent; box-shadow:none`) — 아이콘 2.6rem + 이름만 존재.
- 홀수/짝수 카드가 각각 -1.5deg/+1.5deg 회전 → 손으로 늘어놓은 느낌.
- 모든 몬스터 아이콘은 `idle-float` 애니메이션(2.2초 주기 상하 6px 이동 + 살짝 확대) 적용, elite는 아이콘에 붉은 드롭섀도 추가.

**리소스 구현 규칙**: 카드 배경이 없으므로 몬스터 스프라이트는 **알파 채널 있는 단독 이미지**(카드 프레임 없이)로 제작. 권장 규격 72×72px 투명 PNG, `filter: drop-shadow(...)`를 유지할 수 있도록 실루엣이 뚜렷해야 함(그림자를 이미지에 미리 굽지 말 것 — CSS가 실시간으로 그림자를 씌운다).

### 2-2. 성벽(`.wall-frame`) — 그리드 타일이 아닌 "프레임 자체가 건물"

- 현재는 `border: 9px solid #8a7a63`(CSS 색상 테두리)로만 표현됨. 미건설 시 `dashed` + 투명 배경.
- 클릭 이벤트가 `#wall-frame`에 바인딩되어 있고, `#board` 내부 클릭은 무시(`e.target.closest('#board')`)하도록 이미 분리되어 있음.

**리소스 구현 규칙**: 실제 성벽 텍스처를 넣을 때는 `border-image`(9-slice, 최소 30px 조각)로 교체하되, **`#board`를 덮지 않는 프레임 전용 레이어**여야 한다. 즉 성벽 이미지는 그리드 셀 크기와 무관하게 `.wall-frame`의 바깥 테두리에만 그려지고, `wall-badge`(상단 배지)는 건설 레벨 표시용 별도 스프라이트로 얹는다.

## 3. 도시 보드(`#board`) — 타일 그리드 배치 규칙

- Grid: **10열 × 4행**, 열 폭 **78px**, 행 높이 `minmax(84px, auto)`, gap **6px**, 좌우 패딩 24px.
- 좌표는 고정형(자유 이동 불가), 성(castle)·여관(tavern)만 2칸(span 2)을 차지하며 그리드 중앙(5~6열)에 위치:

| id | 타입 | col | row | span |
|---|---|---|---|---|
| defense(방어탑) | 4 | 1 | 1 |
| watch(감시탑) | 7 | 1 | 1 |
| academy(아카데미) | 4 | 2 | 1 |
| **castle(성)** | 5 | 2 | **2** |
| storage(자원보호소) | 7 | 2 | 1 |
| **tavern(여관)** | 5 | 3 | **2** |
| plot1~14 | 자유 선택(병영/농장/벌목장/채석장) | - | - | - |

- **타일 시각 규칙(v1과 가장 크게 다른 부분)**: `.plot`은 이제 `background:transparent; box-shadow:none`이다. 즉 건물은 카드 패널 없이 **아이콘 하나(2.8rem, drop-shadow 적용)가 빈 배경 위에 떠 있는 형태**다. hover 시 아이콘만 `translateY(-3px) scale(1.06)`, 가동 중(`working`/`training`)이면 `idle-float` + `pulse-glow-icon`(그림자가 주황색으로 맥동) 동시 적용.

**리소스 구현 규칙**:
1. `#board`에 **바닥 텍스처(잔디/돌길)를 background-image로 반드시 깔아야** 한다 — 그렇지 않으면 아이콘이 허공에 뜬 것처럼 보인다.
2. 건물 스프라이트는 몬스터와 동일하게 **프레임 없는 투명 PNG**, 하단 기준 정렬, `overflow: visible`로 세로 초과분은 허용하되 가로는 셀(78px)을 넘지 않게 제작.
3. 미건설 부지(`tile-empty`)는 `dashed` 테두리 + 반투명 십자/초석 아이콘으로 유지하거나, 별도 "빈 초석" 스프라이트로 교체 가능.
4. 레벨 티어는 `MAX_LEVEL=20` 기준 3단계(Lv1-6/7-13/14-20) 제작을 권장(제작비 절감), 파일명 `assets/buildings/{type}_{tier}.png`.

## 4. 건물 상세 모달(`.modal-xwide`, 1140px) 내부 배치

- `.modal-cols-3`(flex-wrap) 안에 `.modal-section`(둥근 패널, `--bg` 색) 카드가 최대 3개 나란히: **①정보/레벨업 비교** → **②영웅 배치**(방어탑·감시탑·자원보호소·여관은 `noHeroBonus`라 이 칼럼이 아예 빠짐) → **③(병영일 때만) 병력 훈련**.
- ①의 `.compare-line`은 "현재 → 다음 레벨" 생산량을 화살표(⬇️)로 좌우 비교하는 한 줄 배너 — 새 스탯을 추가할 때도 이 비교 줄 패턴을 재사용할 것.

**리소스 구현 규칙**: 모달 안에서는 보드와 달리 **패널 배경이 있으므로**(`.modal-section` = `--bg` 색 채움) 건물 아이콘을 크게(64~96px) 다시 보여줄 자리가 필요하면 `<h2>` 옆에 배치하고, 보드용 스프라이트를 그대로 재사용 가능(별도 고해상도 버전 불필요).

## 5. 정복 맵 화면(`#screen-worldmap`) + 침략 모달(`#modal-worldcastles`)

> ⚠️ **2026-08-12 전면 재작성** — 이 절은 원래 "월드맵(NPC 성 20개)이 지그재그로 배치된
> 전용 화면"을 설명했다. 그 화면은 이후 실제 플레이어끼리 겨루는 **정복(PvP) 맵**으로
> 완전히 대체됐고, NPC 성 20개는 별도의 **"🏯 침략" 모달**로 분리됐다. 아래는 현재 구조다.

### 5-1. 정복 맵(`#screen-worldmap`) — PvP, 200×200 드래그형 그리드

- 모달이 아니라 **`.kingdom-stage`를 완전히 대체하는 화면 전환**(`showScreen('worldmap')`).
  더 이상 지그재그 퍼센트 좌표가 아니라 **200×200 정수 좌표 그리드**이고, 서버(`GET
  /api/conquest/tiles`)에서 뷰포트 범위(15×9칸)만 그때그때 받아와 렌더링한다
- `.worldmap-viewport`(뷰포트, `overflow:hidden`) 안에 `.worldmap-field`(실제 타일이 그려지는
  캔버스)가 있고, 카메라 좌표(`conquestCamera`) 기준으로 타일 픽셀 위치를 계산한다
  (`CONQUEST_TILE_PX` 등, `game.js` 참고)
- **드래그로 이동**: 뷰포트에 `pointerdown/move/up`을 걸어 카메라 좌표를 옮긴다. 미니맵
  (`.conquest-minimap`)과 타일 클릭 시 상세 정보 패널(`.conquest-tile-info`)도 있다
- 내 성 진입 조건은 **성 Lv.5 이상**(서버가 강제) — 진입 시 무작위 빈 칸에 배치되고
  30분 신규 보호를 받는다

**리소스 구현 규칙**: 배경은 여전히 `.worldmap-field`에 통짜 타일링 텍스처를 깔 수 있지만,
좌표계가 퍼센트가 아니라 **`CONQUEST_TILE_PX` 단위 그리드**로 바뀌었으므로 옛 지그재그
배치 공식(`castlePosition`)은 더 이상 존재하지 않는다.

### 5-2. 침략 모달(`#modal-worldcastles`) — PvE, NPC 성 20개

- topbar "🏯 침략" 버튼(`#btn-worldcastles`) → 다른 모달들과 동일한 `.modal-overlay` 패턴
  (`modal-wide`), 지그재그 화면이 아니라 **세로로 나열된 목록**(`.raid-list`/`.raid-row`
  클래스를 보스 레이드 모달과 공유해 재사용 — 새 CSS를 만들지 않았다)
- 각 행: 성 아이콘(레벨 구간별 4티어 `castle_t1`~`t4`, `worldCastleIconHTML`) · 이름(플레이버
  텍스트)+레벨 · 스탯(⚔️🛡️❤️) · 현재 약탈 가능 자원(`bank`) 미리보기 · 공격 버튼
- 공격 버튼 클릭 시 모달을 닫고 기존 교전 모달(`openEngageModal("castle", id)`)로 이어진다
  — 별도의 전용 UI를 새로 만들지 않고 몬스터/레이드와 같은 교전 흐름을 재사용

**리소스 구현 규칙**: 성 아이콘 에셋(4티어)은 그대로 재사용 가능 — 화면이 모달로
바뀌었을 뿐 시각 자산 자체는 안 바뀌었다.

## 6. 타이틀 / 종료 화면

- `position:fixed; inset:0; z-index:500`, 방사형 그라디언트 배경(`--panel` → `--bg`).
- 중앙 정렬된 `.title-card` 하나(로고 텍스트 + 태그라인 + 버튼 1개).

**리소스 구현 규칙**: 로고를 이미지로 교체할 자리(`.title-logo`)와, 배경에 은은한 신화적 실루엣(올림포스 산/구름)을 넣고 싶다면 `.screen-title`의 `background`에 이미지 레이어를 추가하되 방사형 그라디언트는 이미지 위에 반투명으로 얹어 텍스트 가독성을 유지할 것.

## 7. 공통 모션 규칙 (리소스 제작 시 반드시 지킬 것)

- 모든 "떠 있는" 아이콘류(건물/몬스터/월드맵 성)는 **idle-float**(2.2~3초 주기, 상하 6px, 살짝 확대)를 기본 적용받는다. 이미지 자체에 그림자나 좌우 비대칭 포즈를 넣으면 애니메이션과 충돌하니, **정면/좌우 대칭 실루엣**으로 제작.
- 그림자는 이미지에 굽지 않고 CSS `filter: drop-shadow(...)`로 실시간 적용되므로, 배경이 투명해야 그림자가 정상적으로 보인다.

## 8. 반응형 규칙
